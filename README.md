# TOON on personal machines

The **Omarchy integration effort**: can a personal machine hold a TOON identity, pay for things
as a **client**, and eventually be a **connector** that other operators peer with?

This repository is **private** and holds only planning. It exists because the effort reads
`toon-protocol/provider` and `toon-protocol/TOON_Network`, which are private, and the
connector's own issue tracker is public.

- **The map** is issue [#1](https://github.com/toon-protocol/omarchy/issues/1), labelled
  `wayfinder:map`. Its tickets are its child issues.
- **`docs/research/`** holds the notes that resolved the research tickets. One file per ticket,
  linked from the ticket.

Vocabulary is `toon-protocol/connector`'s `CONTEXT.md`; `docs/adr/` there is the tiebreaker.
No code lives here yet, and which repository eventually owns the work is
[a ticket](https://github.com/toon-protocol/omarchy/issues/11), not a premise.
